## 中

### 中-1 `upgradeChanceFor` 的說明還寫舊機率，就掛在改掉的那三行正上方

`src/engine/run.ts:385`

那行說明寫「第一關 10%、第二關 20%、第三關 40%」，`:389` 回的卻是 `0.4 / 0.25 / 0.2`。同一句話還有三份沒改：`src/engine/rewards.ts:14`（「第一關一成、第二關兩成」）、`src/engine/rewards.ts:73`、`src/engine/run.ts:184`。下一個人來調這個機率，讀到的四段文字全是錯的。

修法：四處都改成「第一關 20%、第二關 25%、第三關 40%」，或乾脆把數字從註解裡拿掉、只寫「見 `upgradeChanceFor`」。

### 中-2 小牌的規則文字比牌名還大，字級順序倒過來了

`src/ui/styles/components.css:415`（規則 13px）對 `:411`（牌名 12.75px）

戰鬥手牌走的就是 `.card.small` 這一檔。改完之後規則文字 13px、粗體 700，牌名 12.75px、粗體——整張牌上字最大的是規則不是名字。大牌那邊也只是打平（`:354` 牌名 15px 對 `:361` 規則 15px，兩邊都 700），牌名只剩底色那條襯底在撐階層。玩家反應的是「看不清」，把規則放大是對的，但牌名沒跟著走。

修法：`.card.small .card-name` 加到 14px、`.card-name` 加到 16～17px（牌名一行放得下，`.card-name` 是 `width: 100%`、內容寬 152px，最長的「絕學·借力使力＋」8 字在 17px 也只有 136px）。

### 中-3 名詞表的守衛只守得住 10，守不住 15

`tests/engine/audit0905b.test.ts:26-27`

那條測試是 2026-09-05 專門為了「改常數忘了改名詞表」寫的，內容是 `expect(glossary['魔氣暴走']).toContain(\`第 ${RAMPAGE_TURN} 回合\`)`。名詞表現在多了「（關主戰第 15 回合起）」這半句（`src/content/glossary.ts:4`），但沒有任何測試比對 `BOSS_RAMPAGE_TURN`。之後有人把關主的 15 調成 12，名詞表會靜靜說謊，而這正是那條測試當初要防的事。

修法：同一支測試補一行 `expect(glossary['魔氣暴走']).toContain(\`第 ${BOSS_RAMPAGE_TURN} 回合\`)`。

### 中-4 三張對照截圖是 12px／圖縮 8px，出貨的是 13px／圖縮 16px

`docs/牌面字體對照_2026-09-06/3_加粗放大到12px_圖縮8px.png` 對 `src/ui/styles/components.css:415`、`:407`

檔名寫得很清楚：拿去比的第三個方案是「加粗放大到 12px、圖縮 8px」。實際出貨的小牌是 13px、圖從 102 縮到 86（縮 16px）。也就是**真正上線的那組數字沒有任何一張截圖看過**，而這一版的餘裕只有一個像素出頭（見中-5），差 1px 就會開始靠自動縮字收尾。

修法：照 13px／86px 再截一張同場景的圖收進那個資料夾，順手看一眼「封印解除＋」那種四行牌的最後一行有沒有貼到牌型標籤。

### 中-5 小牌四行的餘裕只有約 1.1 像素，換個字體就會踩到自動縮字

`src/ui/styles/components.css:390-416`

我用 `C:\Windows\Fonts\msjh.ttc` 的 `hhea` 度量算：微軟正黑體的 `normal` 行高比是 2203/2048 加 521/2048＝**1.3301**（`fsSelection` 沒開 `USE_TYPO_METRICS`，所以瀏覽器吃的是這組）。小牌可用高度逐項算給你看：

```
牌內高          213 − 邊框 2.5×2                     = 208.0
− 圖            上邊距 6.8 + 高 86                   = 92.8
− 牌名          1.7 + 1 + 1 + 12.75×1.3301 + 2 + 1  = 23.66
− 牌型標籤      1 + 9.35×1.3301 + 3.4 + 4           = 20.84
                                                      -------
規則文字拿到                                          70.70（扣內距 2 → 內容 68.71）
四行需要        4 × 13 × 1.3                        = 67.60
餘裕                                                  1.11 像素
```

最長的牌是「封印解除＋」42 字（`docs/牌池總表.json`，`describeCard` 產的同一份文字）：小牌內容寬 130px，30 個全形字 390px 加 4 個數字與 8 個空白約 50px，合計約 440px，除以 130＝3.4 行，四行放得下。大牌同一算法餘裕 3.4 像素（可用 83.4、四行要 78），比較寬鬆。

問題在 1.11 這個數字只對 Windows 成立。字體堆疊第二、三順位的 `PingFang TC`、`Noto Sans TC` 的 `normal` 行高比約 1.40～1.45，代進去牌名與標籤各長 1.5～2 像素，四行就會溢出 1～2 像素，只能靠 `fitCardText` 退到 12.5px——非 Windows 玩家看到的其實不是拍板的 13px。

修法（挑一個就夠）：`.card.small .card-type` 的 `margin-bottom` 從 4px 收成 3px（大牌同理 4→3），或小牌圖高 86→84。兩者都能把餘裕拉到三像素以上，四行在三種字體下都穩。

`src/ui/cardview.ts:70`

## 查過確認沒問題的

**內容數字與文字**

- 舊字眼精掃：活程式碼與玩家看得到的文字裡沒有殘留的「反彈 5」「逆鱗 5」「同生共死（波斯）」。`src/content/enemies.ts` 另外三處 `thorns: 3`（`:897` 老住持、`:1088` 虛無貓）本來就是 3，不是漏改。`docs/設計總覽.md:28` 講的是影子小貓那組復活組，跟波斯無關；`docs/怪物擴充_第三波_設計稿.md:17` 的「reviveHp 12」講的是紙燈籠，正確。
- 「每回合 +1」殘留：`src/content/enemies.ts:682` 的行尾註解把新舊兩版都寫清楚了（「第五輪每回合 +1；第二輪平衡 2026-09-06 放慢成每 3 回合」），沒有誤導。
- 名詞表：`src/content/glossary.ts:4` 兩個回合數都寫了，`tests/content/glossary.test.ts` 的必備詞條清單與「結尾不加喵」兩條都還過。`src/ui/itemcompendium.ts` 與其他圖鑑沒有第二處寫死暴走回合。
- `git grep RAMPAGE_TURN`：程式碼裡只剩 `src/engine/combat.ts:181-185` 宣告、`:245-249` 使用、`src/ui/screens/combat.ts:7/587` 匯入使用，三支測試（`rampage`、`audit0905b`、`balance_0905`）用常數而非字面值。畫面的牌子與引擎確定走同一支函式，不會出現「牌子掛了但沒加爪力」。

- 牌型標籤沒被擠：`min-height: 0` 正是解掉 flex 項目「自動最小尺寸＝內容高度」的那條，`.card-type` 的 `flex-basis` 是 auto、不會被壓縮，加上 `.card-text` 是 `flex-basis: 0` 只吃剩餘空間，標籤位置穩。
