- 觸發情境：兩台開局、各自在看連線序章幻燈片（09-17 新加，以前是直接進地圖）。其中一台（A）的同伴關掉分頁或斷線逾時 → A 跳出紅色橫幅（z-index 9999，壓在幻燈片上面，點得到）→ A 按「回標題」→ `leaveCoop()` 把 `coop` 清成 null、座位歸 0，畫面換到標題；但幻燈片掛在疊層、不在 `closeScreenModals` 的清單裡，所以還蓋在標題上面。A 把剩下幾張點完 → `onDone` → `app.show('map')`，`app.run` 還是那個兩人局 → 地圖以**單機模式**開起這個兩人局。A 走完第一格 → `backToMap()` → `save()` 看到 `coop` 是 null → `saveRun(兩人局)`，**原本的單機存檔被蓋掉**（橫幅上還寫著「存檔不會壞」）。
- 信心：確認（程式路徑逐步讀過；觸發要「同伴在序章中離開＋在序章沒看完前按回標題」，窄但真實）。
- 修法方向（僅供參考）：`playPrologue` 的 `after` 在連線局先檢查 `app.coop` 還在、`app.run` 還是同一局；或 `leaveCoop` 時把 `app.run` 清掉。

## 查過、沒有發現問題的項目
- 飛行物接著演（`projectile-flight.ts` 的 `joinElapsed`）、勝利壓住（`holdWin`）、同伴牌掛頭上（`mateSig`／`matePlay`）、台詞泡泡、對白頭像藏格：都只讀狀態、只動畫面節點，沒有寫回引擎。唯一動到 `cs` 的是 `beforeApply` 暫時把 `cs.log` 換成最後一行再深複製，`finally` 會還原（`combat.ts:3606-3617`）；批次重播只在複本上套用，引擎沒有模組層級的計數器或共用狀態會被複本動到。
- 演出例外：單張路徑（`3902-3920`）與演出佇列（`2642-2649`、`2635`）都有接住並照常收尾。
- 指紋 `hash.ts`：已含蓄氣 `q`、下一擊準備 `nab`、集中精神 `egb`、能力牌細項（含 `firedTurn`、效果內容）；師父換血條走 `e.hp/maxHp/phase`；看破是狀態，照狀態列收；沒有收純畫面欄位。只少了新欄位 `echoUsed`，但它回合開頭就重設、同一回合的差異會先反映在血量或手牌上，不影響偵測。
- 非決定性：`src/engine/**` 沒有 `Math.random`／`Date`／模組層級可變狀態；新加的事件「交換被擋下」跳過擲骰那條，兩台用同一份整局狀態判斷，結果一致；序章、塔頂段落寫的 `run.flags` 不在整局指紋裡、也不是任何事件的 `requiresFlag`。沒有邏輯依載圖完成時間決定。
- 心跳計時器：`die()` 會清；接回成功時重設；背景與凍住那段不量。大廳在離開後才連上的線路都會 `tx.close()`。
- 換畫面：`closeScreenModals` 只收牌組、挑牌、秘寶清單，不叫回呼、會解鎖；同一畫面重畫不收，戰利品不能取消的升級視窗照留。戰利品頁「換忍具」視窗刻意沒收（原本就設計成換頁後還能回答），沒有被這次改動破壞。
- 第四隻貓混搭：大廳改照 `HEROES` 清單認角色；座位、立繪、動作來源都照 `heroOf(q)`；鏡中對手照座位 0（兩台一樣）。沒看到寫死兩隻貓的判斷。
- 戰鬥畫面改成按需載入：`startFight` 會等模組載好才進場，`attach(cs)` 仍在整支最後、分出勝負 `attach(null)`；排隊、場次、回合號那套規則沒被動到。
