## ② 重複感實測

**做法**：照 `smartRun` 的決策（同樣的挑路、挑選項、買東西規則）每隻跑 200 局，共 800 局、難度 1。機器人平均只爬到 22.5F（通關 1.9%），比真人短很多，所以另外挑出「到得了第三關」的 81 局當「完整一局」的近似——**真人的重複感要看右欄**。

| 每局平均 | 全部 800 局 | 完整局 81 局 |
|---|---|---|
| 爬到幾樓 | 22.5F | 41.8F |
| 遇到事件（不含 5F） | 3.7 篇 | 6.9 篇 |
| 5F 秘笈 | 1.6 次 | **2.9 次（每關一次，同一篇）** |
| 拿到秘寶（不含起始） | 4.2 件 | 9.7 件 |
| 看到秘寶（拿到＋貨架＋過關三選一，去重） | 10.6 件 | 24.2 件 |
| 拿到忍具 | 4.7 支 | 8.7 支 |
| 看到忍具（去重） | 10.1 支 | **17.2 支（35 支的一半）** |
| 同一局裡重複遇到同一篇事件 | 0 | 0 |

完整一局看掉各池的比例：**常見 11.7/30（39%）、大魔物 5.4/24（23%）、塔主 7.0/19（37%）**。

**連續兩局（同角色、相鄰種子）的重疊：**

| 項目 | 後一局看到的裡「上一局也看過」的比例（全部／完整局） | 至少撞到一個的局（全部／完整局） |
|---|---|---|
| 事件 | 10.2%／18.4% | 32%／**77%** |
| 拿到的秘寶 | 9.3%／24.0% | 31%／**100%** |
| 看到的秘寶 | 18.7%／**35.7%** | 74%／100% |
| 拿到的忍具 | 12.4%／21.5% | 44%／83% |
| 看到的忍具 | 28.9%／**48.5%** | 91%／100% |

**最常出現的前 10 名：**

- 事件（全部）：卡住的小貓 13%、賣藥的三花貓、倒了的神龕、曬太陽、師父的影子、鏡子走廊、深藏不露、兵器架、好高的貓抓柱、留下買路財（各約 12%）——**很平，沒有哪篇特別常出**。
- 事件（完整局）：賣藥的三花貓 31%、卡住的小貓、會哭的牆、很貪心的商人、閉關（各 25%）、很重的門、掉在地上的卷軸、好高的貓抓柱、很吵的廚房（各 23%）、可疑的飯糰攤 22%。
- 拿到的秘寶：塔主令牌 48%、鮪魚罐頭、鈴鐺、掌門腰帶（各 10%）、護腕、飯糰袋、魚骨頭、破卷軸、金飯碗、貓薄荷（各 9%）。
- 看到的秘寶（完整局）：塔主令牌 100%、破卷軸 52%、魚骨頭 47%、幸運錢幣 46%、軟墊、護腕、斗笠、忍具袋、貪吃錢袋、毛線手套（各 43%）——前十名全是常見池，因為每間罐頭鋪擺兩件常見、完整一局逛 5.3 間。
- 拿到的忍具：加倍奉還 16%、爪力粉 15%、鏡片、順手牽羊爪、鞭炮、三連針、飯糰（各 14%）、剪刺鉗、小被子、麻繩（各 13%）。

**後集遇得到嗎**：做過前集、活到第二關的局，遇到後集的比例是江湖救急 68%、分糧救急 38%、買路財 35%。角色專屬事件每局平均只遇到 0.26～0.37 篇，球球是 0。

**解讀**：

1. **抽法本身是平均的、同一局也不會重複**，所以重複感不是抽法偏了，是池子小：完整一局就看掉常見池四成、塔主池快四成、忍具一半。
2. **全遊戲重複最重的單一內容是 5F 秘笈**：每一關都是同一篇、同一張圖，完整一局看三次，每局都看。
3. 按數字排：忍具最重（相鄰兩局看到的忍具一半重疊）→ 秘寶（三成六）→ 事件（一成八）。但事件圖文長、一眼就認得，**體感比數字重**。
4. 過關三選一的塔主池 19 件、一局抽兩次三選一，第二局起就開始撞熟面孔（使用者 09-15 回報過的那件事，池子補到 19 件之後仍然如此）。

## ③ 每件內容的成本

### 事件圖的規則（查過程式與素材清單）

- 主圖鍵 `bg/event_<代號>`（球球版）＋`bg/event_<角色>_<代號>`（菲菲、噹噹、封封版）；結果圖 `bg/event_<代號>_r<選項序號>` 也是四份。挑圖走 `src/ui/assets.ts` 的 `eventArtKey`：有自己的版本用自己的，沒有退回球球那張。
- **`data-art-cast`**（插圖裡畫了誰）是照檔名推的，不是手抄：有角色前綴＝畫的是那一位；沒前綴但有菲菲版＝畫了球球；兩者都沒有＝純場景。目前只拿來決定 5F 對白要不要放頭像。
- **連線混搭**：兩台各自照「本機這一位」挑圖與文字，所以共用事件不必多畫；例外只有鏡子走廊（照座位 0 挑，圖裡沒有本機這隻時旁邊放本機立繪，`eventSidePortrait`）。角色專屬事件在連線局不排。
- 實數：37 篇共用事件（不含 5F）共 384 張，**平均一篇 10.4 張**（2.6 個鍵 × 四隻）；角色專屬事件一篇平均 3.3 張（只畫那一隻，圖檔用 `bg/event_<角色>_<事件>`）。素材清單裡事件圖 443 張。
- 文字：球球原文寫在 `src/content/events.ts`；菲菲走「換名字＋引號句對照」（`FEIFEI_EVENT_LINES` 88 句、整段覆寫 `FEIFEI_EVENT_TEXT` 6 段）；噹噹、封封整段改寫（`DANGDANG_EVENT_TEXT` 124 段、`FENGFENG_EVENT_TEXT` 203 段）。測試會逼每一段都有他們的版本（`tests/content/fengfeng_shared_dialogue.test.ts`、`dangdang_no_ninja.test.ts`、`feifei_event_lines.test.ts`），**加一篇共用事件等於一次寫四份**。共用事件平均 5.4 段、球球原文約 224 字，四份合計約 900 字。

## ④ 跟殺戮尖塔比

殺戮尖塔（Slay the Spire）的數字憑記憶、一律標「約」；二代我只知道公開預告層級的東西，**沒查證，只能當方向參考**。

| 項目 | 爪破魔塔 | 殺戮尖塔一代（約） | 我們少在哪 |
|---|---|---|---|
| 秘寶總數 | 77 | 約 180 | 少一半以上；四隻共用一個池 |
| 秘寶分級 | 起始／常見／大魔物／塔主 | 起始／普通／罕見／稀有／頭目／商店限定／事件限定 | **池內沒有稀有度**、沒有商店限定、沒有事件限定——拿到的東西跟「在哪拿的」沒關係 |
| 角色專屬秘寶 | 起始各 1，其餘 0 | 每角色約十件上下 | 菲菲、封封的機制零放大器 |
| 帶代價的秘寶 | 4 件，**頭目級 0 件** | 頭目秘寶大多是「多一點能量＋一個代價」 | 過關三選一只有純好處，沒有要猶豫的選擇 |
| 計數型秘寶 | 0 | 約十件（每 N 張攻擊、每 N 回合、跨戰鬥累計） | 沒有「快集滿了」的期待感 |
| 忍具（藥水） | 35、無稀有度、平均抽 | 約 40 多、三級稀有度、有角色專屬、掉落率沒掉會漸增 | 沒有「撿到好東西」的驚喜 |
| 事件 | 50 | 約 50 左右，外加開局的涅奧（Neow）祝福 | 數量接近，但**我們每篇要畫四份**，成本高很多 |
| 事件分關 | 32 篇裡 29 篇三關都有 | 大多數事件分關，另有一批跨關的神龕類 | 三關的事件沒有「這一層的味道」 |
| 問號格 | 一定是事件 | 可能變成戰鬥、商店、寶箱，機率會累加 | 地圖上的事件格完全可預測 |
| 開局選擇 | 無 | 涅奧四選一（一個安全、一個有代價） | 每局開場都一樣 |
| 條件選項 | 無 | 部分事件看金幣、牌組、秘寶開選項 | 選項跟你這一局養成什麼沒關係 |

殺戮尖塔二代（2026 搶先體驗）據預告：每一關開頭都有一次類似涅奧的祝福選擇、同一關的位置有不同地區輪替。**這兩點我沒查證**，但方向跟下面第⑥節的「開局祝福」「關卡限定事件」一致。

我們的強項也要講：**每篇事件四隻各有自己的圖與口吻**，這是殺戮尖塔沒有的故事感，但也是事件擴充最大的成本瓶頸——所以下面提案裡事件的「量」會壓得比秘寶保守，改用結構去補變化。

## ⑥ 結構性變化的做法

| 做法 | 玩家會感受到什麼 | 要改哪些程式 | 風險 |
|---|---|---|---|
| 5F 秘笈三關三版 | 最常重複的一幕（每局三次）變成三段不同的師父線索，一路往上有劇情推進 | `events.ts` 的固定事件改成每關一個；`map.ts` 生成與驗證、`run.ts` 的 `chooseNode`、`event.ts` 的對白；6 支測試 | 小：舊存檔地圖裡的 `daxia_teach` 要繼續合法；5F 對白「只播一次」要決定是不是每版各播一次 |
| 條件選項 | 「我這局養毒，所以多一條路」——選項跟這一局的養成有關 | `EventChoice` 加出現條件、事件畫面顯示原因、機器人估值讀得到 | 中：條件寫錯會讓選項靜靜消失；要有測試逐條核對 |
| 事件鏈延長 | 第一關做的選擇在第三關有回報，會想「這次換另一邊看看」 | 沿用旗標＋後集；鏈的旗標收進整局指紋 | 小：後集命中率要量（現在最低只有 35%） |
| 關卡限定事件 | 塔下、塔中、塔頂各有自己的味道 | 沿用 `acts` | 小：每關可排的池變小一點，要確認不夠填時的墊檔 |
| 角色專屬事件補齊 | 球球終於有自己的故事；每隻都常遇到「只有我才會碰到的事」 | 沿用 `hero`；球球專屬的圖要排進延後名單 | 小：連線局不排，連線要另外用連線限定事件補 |
| 忍具稀有度 | 開到稀有忍具會「哇」一聲；普通忍具變得可以隨手用 | `PotionDef`、`rollPotion`、罐頭鋪售價 | 小：所有種子的結果都會變，定錨要重錄 |
| 代價型塔主秘寶 | 過關三選一開始要猶豫：多一顆飯糰值不值得不能睡？ | 沿用；少數要驗負值 | 中：多飯糰很強，要靠量尺確認不會一面倒 |
| 計數型秘寶 | 「還差兩張就爆發了」的期待感 | 新掛鉤＋玩家身上的計數欄位；秘寶圖示上要畫數字 | 中：新狀態要進存檔、指紋；畫面要顯示進度 |
| 秘寶組合技 | 看到套組的另一件會特別想拿，路線有目標 | 套組欄位、圖鑑、獲得時提示 | 中：套組太強會讓每局都追同一套，反而更重複；只給小加成 |
| 事件限定／罐頭鋪限定池 | 「這件只有這裡拿得到」，逛店與走事件格更有理由 | `RelicPool` 多兩個值、取得管道、機器人估值 | 小：池子各只有三五件，要跟「同局開過不再開」一起用 |
| 詛咒型秘寶與解除 | 拿了好處背著麻煩，之後遇到能解除的事件會很爽 | 事件結果加「淨化」 | 中：解除管道太少就變純懲罰 |
| 罐頭鋪店主輪替 | 每間罐頭鋪不一樣，會為了某位店主繞路 | `makeShop` 依店主換貨架規則；店主台詞四隻口吻 | 小：價格規則多一層，要跟零錢罐、貪吃錢袋一起測 |
| 開局祝福 | 每局開場就不一樣，一開始就有選擇 | 新畫面、`newRun` 之後插一步；連線兩人各選 | 中：開場多一步，要能一鍵跳過 |
| 問號格變化 | 事件格不再百分之百可預測 | `enterEvent` 依機率改節點種類 | 中：使用者可能不喜歡被騙；機率要低、畫面要演清楚 |
| 稀有事件 | 很久才遇一次，會記得、會跟人說 | 事件加權重 | 小 |
| 連線限定事件 | 兩個人一起玩時有專屬的故事與互相取捨 | 連線限定旗標、座位不對稱結果、共用立繪版面 | 中：兩人投票流程已經有，但「一人得一人失」要新做 |

## ⑦ 風險與守門

**平衡怎麼量**

1. 先做第〇批的量尺：每件秘寶、每支忍具都要有評分，評分來自實測（開局塞一件跑 600 局看平均樓層差），不是手填。
2. 每批做完，四隻各跑 600 局、兩組種子（`SMART_N=600 SMART_HERO=… npx vitest run tests/smart.report.test.ts`），對照通關率、到達第二三關比例、各池拿到件數。
3. **機器人不會用的機制不上線**：
   - 第一批全部是被動發動（開戰、回合開始、被打、打出攻擊），機器人自動吃得到好處；但「這回合沒攻擊才發動」那一型機器人不會刻意配合，量出來會偏低，這次沒有新增這一型。
   - 每支新忍具必須在 `maybePotion` 有使用規則；用忍具使用率報表抓「拿了不用」的（低於兩成就是規則沒寫好）。
   - 第二批的新掛鉤（蓄氣滿、花蓄氣、閃避……）要先教機器人怎麼估，再開放進池子。
4. 事件估值：`eventValue` 已經涵蓋所有結果類型（新類型不寫估值型別檢查就會擋），但秘寶一律算 24／34 分，第〇批要改成讀量尺分數。

**連線決定性**

- 新效果只能用 `runRng(run)` 或戰鬥裡的 `cs.rng`，不能碰 `Math.random`、時間。
- 新狀態要進指紋：戰鬥裡的（計數器、保命旗標）進 `combatFingerprint`；整局的（跨場計數器、詛咒標記、鏈的旗標）進 `runFingerprint`。**注意 `runFingerprint` 現在只收 `event:`、`sequel:` 開頭的旗標**，`relic_seen:` 與前集旗標（像 `toll_paid`）都沒收；新做的鏈建議用固定前綴並收進去。
- 兩人的秘寶二選一走 `rollRelicChoices`；新池也要能這樣抽。罐頭鋪是一人一份、價格各算各的，新規則照這個形狀寫。

**存檔相容**

- 只加不改：秘寶、忍具、事件的代號不能改名、不能刪（刪事件會讓存檔驗證失敗、整份存檔被清，`save.ts` 會檢查地圖上每一格的事件代號）。
- 新欄位一律可選，載入時補預設值（`flags` 就是這樣補的）。
- 5F 改成每關一版時，舊存檔地圖上的 `daxia_teach` 要繼續合法。

**首載體積**

- 程式：9/22 建置 661.6/680 KB（主控說目前剩約 5 KB）。秘寶一件約 0.23 KB、忍具約 0.22 KB、共用事件約 4 KB（四份文字）。**第一批合計約 18 KB，沒有第〇批的分包一定超標**。
- 圖片：10.18/10.6 MB。秘寶與忍具圖示算首載（一張約 3.3 KB，第一批 28 張約 95 KB，放得下）；三關都能遇到的共用事件，球球版主圖算首載（約 27 KB 一張），第〇批的 0-2 做完才不受限。限關事件、菲菲噹噹封封版、結果圖都是延後載。

**其他守門**

- 同一顆種子的結果會變：`tests/engine/bot.test.ts` 的定錨要重錄（`python tools/rerecord_bot_anchors.py`）；數量測試要改（`tests/content/relics.test.ts` 的 77 與 35、`tests/content/events.test.ts` 的 50）。
- 結果圖命名一律 `<代號>_r<選項序號>`（`tools/event_result_art.test.ts` 會擋）；事件圖沒到齊先標 `artPending`，不排進地圖。秘寶圖沒到會顯示文字牌，但使用者不喜歡破圖，**圖先到再上**。
- 推上線前照慣例派唯讀審查代理看差異；有畫面的東西（新秘寶閃光、飛行物、5F 新版）要實機看過。
