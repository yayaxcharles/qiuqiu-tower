## 高

### 高-1 打倒魔物那一拍，溶解動畫與死亡煙霧插在分段中間，最後一段的數字幾乎看不到

- `src/ui/screens/combat.ts:1210`（`stageHits` 把三段排在第 0／150／300 毫秒）
- `src/ui/screens/combat.ts:1250`（同一輪迴圈裡**同步**掛 `.dead`、`burst(node,'smoke',160)`、放 `enemy_down`）
- `src/ui/styles/combat.css:557` — `.combat .unit.dead { animation: dissolve .8s ease-in forwards; }`，`@keyframes dissolve`（`combat.css:608-612`）是透明度歸零＋灰階＋模糊 6 像素＋下沉。

時間軸攤開來看，三段打倒一隻小怪會變成：

| 時間 | 發生什麼 |
|---|---|
| 0 毫秒 | 第一段的抖動＋數字；**同一瞬間魔物開始溶解** |
| 160 毫秒 | 死亡的那團煙 |
| 150／300 毫秒 | 第二、三段的抖動＋數字（掛在正在溶解的節點上） |
| 800 毫秒 | 節點透明度歸零，第三段那個數字的飄字才走了 500／1100 |

兩個問題疊在一起：一是原本 `combat.ts:1249` 的註解白紙黑字寫「倒下的一團煙晚 160 毫秒放：讓最後那下的斬擊先看完」，現在最後那下在 300 毫秒，順序反過來了；二是收尾那一下的傷害數字掛上去的時候，父節點已經在褪色、轉灰、糊掉，玩家最想看清楚的一下反而最看不清楚。三段以上的牌（連環踢、沾衣十八跌、十二連環、迴旋踢升級版）打出致命一擊是很常見的情形。

補充：關主倒下走的是 `bossFallUids` 那條（白閃慢倒），不掛 `.dead`，所以這條只影響一般魔物。

修法：`e.dead` 時把 `.dead`、煙、`enemy_down` 三樣一起延後 `(staged.length - 1) * 150 + 160` 毫秒再放；或是打倒那一拍把段距壓到 90 毫秒，讓死亡演出仍排在最後一段之後。

## 中

### 中-1 三個傷害數字疊在同一個座標，看起來像一團糊掉的字

- `src/ui/screens/combat.ts:349`（`node.append(floatNum(\`-${amt}\`))`，沒有帶任何位置變化）
- `src/ui/styles/combat.css:558-572` — `.combat .num { left: 50%; top: 28%; font-size: 40px }`，只有 `.num.blocked`（`combat.css:792`）與 `.num.thorn`（`combat.css:795`）另外調過樣式與位置，一般傷害數字全部落在同一點。

照 `@keyframes float`（`combat.css:617-623`）與 1.1 秒的長度換算，間隔 150 毫秒的兩個數字在穩定期只差約 8 個像素，字級卻是 40 像素——重疊約七成，而且比較晚出現的那個還在 1.45 倍放大階段。迴旋踢升級版三段都是 `-7`，畫面上會像一個在抖的 `-7`，不像三個。

抖動、斬擊、音效這三樣確實分開了，所以比原本的單一 `-21` 好；但「數字要看得出三下」這件事只做到一半，離使用者原本的抱怨（「看起來像一下扣 15」）還有距離。

修法：段距 150 → 260 毫秒（三段共 520 毫秒，仍在 650 毫秒的收姿勢時間內），或給每段一個小的水平位移（照序號設 `--dx: -18px / 0 / 18px` 之類）。

## 低

### 低-1 `cs.hits` 整場只加不清

- `src/engine/types.ts:515`、`src/engine/actions.ts:247`

畫面靠 `slice(before.hitsLen)` 取窗口，功能是對的；但這個陣列整場沒有上限也沒人回頭用舊資料，一場二十幾回合的關主戰（龍貓那種）會累積幾百筆。建議在 `startTurn` 清空、或每次 `act()` 之前歸零，`hitsLen` 跟著回零就好。

### 低-2 分段動畫少了 `app.cs === cs` 這道保險

- `src/ui/screens/combat.ts:344-345`

這支只檢查 `node.isConnected`。這一版是安全的（換畫面會 `clear(root)`，節點就 detach 了），但這個檔案裡其他所有延遲回呼都額外檢查 `app.cs === cs`（例如 `combat.ts:1126`、`:1372`、`:1395`）。照著補一行比較保險，也比較一致。

### 低-3 最後一段的抖動會被 650 毫秒的收姿勢定時器切掉

- `src/ui/screens/combat.ts:1344-1356`（`hold` 最少 650 毫秒，時間到就 `classList.remove('attack','hit','dodge','cast')`）
- `src/ui/styles/combat.css:551-554`（`.unit.hit .sprite { animation: shake .4s }`）

三段時最後一次 `.hit` 是 300 毫秒掛上去的，抖動要到 700 毫秒才跑完，650 毫秒就被拆掉——差 50 毫秒，看得出來的機率不高。但如果之後出現四段以上的牌，或中-1 把段距拉長到 260 毫秒（最後一段落在 520 毫秒、要跑到 920 毫秒），這個切斷就會變明顯，`hold` 要一起算進去。

### 低-4 需求第 1 項（畫面）完全沒有測試，且測試有一處靠起手牌組順序

- `tests/engine/fixes_0905c.test.ts` 只釘引擎的 `cs.hits`；`combat.ts:1209-1210` 那個分岔（`opts.attack && staged.length > 1`）沒有任何測試。這個倉庫本來就沒有畫面測試，不算破例，但這次要修的東西正是畫面，至少可以把「哪些情況該走分段」抽成一支純函式來釘。
- `tests/engine/fixes_0905c.test.ts:50-54` 的「單段牌只記一段」靠 `toHand(cs, 1)`＋註解「起手第一張＝貓抓」，實際成立是因為 `STARTER_DECK[0]` 剛好是 `'sanjo'`（`src/content/cards.ts:343-344`）。起手牌組順序一改，這條會靜靜失去意義（不會紅，只是不再測到攻擊牌）。建議直接把一張指名的單段攻擊牌塞進 `extra`。

## 查過確認沒問題的

1. **`cs.hits` 沒有漏初始化的建構路徑。** 全倉庫只有一處建 `CombatState` 物件字面值：`src/engine/combat.ts:33-40`，已加 `hits: []`。`src/engine/bot.ts:13` 的 `playCombat` 與 `src/engine/smartbot.ts` 全程吃現成的 `cs`，不自己建；`tests/helpers.ts` 只造 `Unit`／`PlayerCombat`／`CardInstance`，沒有 `CombatState`。`grep "CombatState = {|as CombatState|<CombatState>"` 在 `src`、`tests`、`tools` 三處只回兩筆，另一筆是 `src/ui/screens/combat.ts:170` 的 `const cs: CombatState = app.cs`（讀取，不是建構）。

2. **存讀檔沒有風險。** `src/engine/save.ts` 從頭到尾只序列化 `RunState`（`saveRun` 是 `JSON.stringify(run)`），而 `RunState`（`src/engine/types.ts:377` 起）沒有任何戰鬥狀態欄位——`save.ts` 裡連 `CombatState` 這個字都沒出現。所以不存在「舊存檔載回來 `hits` 是 undefined、一打就當掉」這條路。`src/ui/app.ts:222` 的 `this.cs = beginCombat(...)` 一律走 `src/engine/run.ts:85` 的 `startCombat`。

3. **`damageEnemy` 三個提早 `return` 的分支不記錄，是對的。** 無敵／調息（`src/engine/actions.ts:209`）、僕從護體（`:211-215`）、隱身閃過（`:226`）三種情形魔物血量都沒動，畫面那邊 `e.hp < b.hp` 本來就不成立，兩邊一致，不會出現「引擎記了一筆但畫面演不出來」或反過來。隱身那條另外由 `combat.ts:1239-1241` 飄「閃過！」，沒被動到。

4. **`Math.min(lose, e.hp)` 的位置與邊界正確。** `actions.ts:247` 夾在虛化封頂（`:241-244`）之後、扣血（`:248`）之前，所以記到的是真的進到血條的量。虛化每段封頂 1、飛行先減半再扣防禦（`:227`）、`ignoreBlock` 走 `lose = dmg`（`:229`）——這三條都在記錄之前跑完。打倒時記剩餘血量：`Math.min` 夾住，測試 `fixes_0905c.test.ts:43-48`（血量 7、連環踢 5×3）釘出 `[5, 2]` 而不是 `[5, 5]`。防禦邊界：`:36-41` 用 7 點防禦釘出 `[0, 3, 5]`、總掉血 8。兩條都不是恆真的斷言。

5. **uid 不會對錯隻。** `makeEnemy`（`src/engine/actions.ts:333`）一律 `uid: cs.nextEnemyUid++`，單調遞增、不回收；分裂（`actions.ts:305-323`）與召喚（`actions.ts:396` 附近的 `summon`）都走它，所以分裂出來的小怪拿到的是新號碼，`before.enemies` 找不到它就直接 `continue`（`combat.ts:1207`）。同生共死的「暫時倒下」是同一個物件、uid 不變，復活（`src/engine/combat.ts:216`）也不換號——同一隻的紀錄仍然對到同一隻。而且畫面每次 `settle` 只取 `slice(before.hitsLen)` 這個窗口，跨拍的舊紀錄不會混進來。

6. **多段迴圈與擊倒的收尾一致。** `src/engine/effects.ts:30-42`：外層跑目標、內層跑 `times`，打倒就 `break`（`:38`），所以不會多記一筆「打在屍體上的 0」。`target: 'all'` 的多段牌（十二連環、手裏劍亂舞、聚葉成刀）是一隻打完三段才換下一隻，但畫面 `filter(h => h.uid === e.uid)` 各自過濾、各自從 0 毫秒起跑，同時演，沒有錯位。

7. **全被擋掉那一拍不會走錯路。** `opts.attack` 為真但總掉血 0 時 `e.hp < b.hp` 不成立，兩條分岔都跳過，照舊由 `combat.ts:1229-1234` 飄「擋住 N」＋盾牌光＋`blocked` 音效——沒有少飄、也沒有多飄。部分被擋（例如 `[0,3,5]`）走分段：第一段只抖不飄數字，「擋住 7」在第 0 毫秒另外飄，跟註解寫的規格一致。

8. **分段的定時器在畫面切換後不會亂噴。** `combat.ts:345` 的 `node.isConnected` 擋在所有副作用（加類別、飄字、特效、音效）之前。`render()`（`:784`）會 `clear(root)`、`patchField()`（`:749`）對有變動的單位 `replaceWith`，兩種都讓舊節點 detach，後面的段就靜靜跳過。打贏交棒是 1300／2400 毫秒後（`:1372`），比三段的 300 毫秒晚很多，正常情況不會被砍。

9. **`hurtSet` 與姿勢判定沒被改壞。** `combat.ts:1188-1198` 那段跟改動前一字不差，`hurtSet` 仍只看 `e.hp < b.hp`（`:1193`），用途在 `:534` 挑受傷立繪；球球那邊的姿勢優先序（`:1179-1186`）也沒動。

10. **TypeScript 沒有漏洞。** `Snap` 只有 `snap()` 一處建（`combat.ts:139-148`），`hitsLen` 有給（`:141`）；`grep "hitsLen"` 全倉庫只有 `:137` 宣告與 `:141` 賦值兩筆，加上 `:1209` 的讀取。`npx tsc --noEmit` 乾淨退出。

11. **魔物身上不會混進雜訊紀錄。** 魔物的噎到是在敵方回合結算的（`src/engine/combat.ts:304`），那一拍 `opts.attack` 是 false，走舊路徑，不會跟攻擊牌的分段混在一起。全倉庫扣魔物血只有 `actions.ts:248` 一處（其餘 `.hp =` 分別是回血 `:389`、換血條 `:276`、召喚吸血 `:412`、復活 `combat.ts:216`，都是加或重設），所以不存在「掉血了卻沒有對應的 hits 紀錄」導致 `staged` 是空的、演出漏掉的情形。

12. **反彈與虛化的互動正確。** 魔物身上的反彈（`actions.ts:238-240`）打的是球球、不會多記魔物的 hits；多段牌打刺蝟師傅會被刺三次，這是既有規則的自然結果，不是這次改壞的。虛化魔物吃 5×3 會記成 `[1,1,1]`，畫面演三下各飄 `-1`——比原本一個 `-3` 清楚。

13. **牌面文字正確。** `src/ui/cardtext.ts:100-103` 對 `times > 1` 產「，連打 N 次」；`docs/牌池總表.json` 那一列的 `up` 是「造成 7 點傷害，連打 3 次，獲得 4 點蜷縮。」，跟 `describeCard` 對得起來（測試 `fixes_0905c.test.ts:59` 有釘 `toContain('造成 7 點傷害，連打 3 次')`）。非升級版的 `text` 沒動，正確。

14. **`docs/牌池總表.json` 的變動確實只有迴旋踢那一列。** `git diff --stat` 顯示該檔 1 增 1 刪。這個檔由 `tools/dump_cards.test.ts:9` 自動重生；我跑完整套 `npx vitest run`（會重跑那支倒檔測試）之後 `git status --short` 與跑之前完全一致，代表重生結果穩定、沒有夾帶其他變動。`tools/out/cardvalue.json` 那份「牌費量表」資料未納入版本控制，不影響這次提交。
