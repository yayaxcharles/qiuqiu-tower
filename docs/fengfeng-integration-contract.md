## 一、穩定識別字與全域規則

### 角色與卡牌識別字

- 角色識別字：fengfeng。
- 卡牌識別字採表內的 fengfeng_ 前綴，不把 FG-C 編號直接當程式識別字。
- 牌池分類沿用現有「起手」「忍術」「絕學」；不新增「劍術」牌池。
- 共 32 種專屬牌：3 種起手牌、25 種單人正常可取得牌、4 種連線限定牌。
- 常見售價 50、罕見售價 75、稀有售價 150；起手牌不可出售，也不進商店與普通獎勵。
- 一張牌只升級一次；規格未列出的欄位維持原值。

### 蓄氣生命週期

- 唯一新增核心資源名稱是「蓄氣」，整數範圍 0～12。不要再新增「內力」「劍意」「劍勢」等同義資源。
- 每位玩家各自保存蓄氣，隊友不能直接花用另一席的蓄氣。
- 每場戰鬥先從 0 開始，再結算起始秘寶；戰鬥結束、撤離或正式倒下時清零；復起不重新發起始秘寶；重連保留目前值。
- 超過 12 的增加量捨去，介面應能提示實際增加量。
- 未明寫消耗蓄氣的普通牌與共用牌，不自動消耗蓄氣。
- 未使用蓄氣不在回合結束時轉成蜷縮、飯糰或生命。

### 一張牌的共同結算順序

1. 驗證玩家階段、合法目標、手牌實例、飯糰費用，以及連線支援是否能提高既有加成。
2. 取得出牌前蓄氣快照，計算 S；非法出牌、飯糰不足、取消選擇都不能扣蓄氣或消耗支援。
3. 扣除飯糰與本牌需要的 S；多段、多目標只扣一次。
4. 結算本牌的主要傷害或效果。蓄氣攻擊以固定基礎值加每點 S 的係數形成一次普通傷害，再套既有爪力、虛弱、易傷、倍傷、防禦與反彈。蓄氣加成不可拆成第二次命中，也不可套用噹噹 damageSpendBlock 的 noStrength 規則。
5. 結算主要效果的反應與既有死亡中止規則；若反彈使施放者倒下，後續目標和牌面後續效果依現行規則停止。
6. 結算依本牌實際 S 的後續獎勵，例如抽牌、蜷縮或回氣；判斷不讀結算後蓄氣值。
7. 最後處理已掛上的循息、收勢、連息等能力觸發。能力產生的效果不是新的出牌事件，不再遞迴觸發能力；施放者倒下或戰鬥已結束時，不執行延遲獎勵。
8. 卡片實例依現有機制進入消耗堆或棄牌堆；卡片消耗與蓄氣消耗是兩件事。

介面預覽與正式結算必須共用同一套蓄氣傷害公式。群攻先共用一次 S，再對各目標各自套普通傷害流程；不因目標數增加蓄氣消耗。

### 連線支援共同規則

- 雙方各自使用手牌與飯糰；以主機接受的出牌順序結算，不使用秒數或同時按鍵。
- 隊友已存活但斷線，仍視為受益對象；隊友倒下或單人時，依各牌規格改給自己；隊友已按結束仍可收到立即蜷縮，但不能接受「下一張攻擊」準備。
- 「下一張攻擊」只套用受益者下一張合法攻擊的第一段、第一個合法敵方目標。先加入基礎傷害，再走原攻擊的正常修正；不放大其他段數、目標、中毒、反彈、秘寶傷害或隊友追加傷害。
- 合法攻擊即消耗下一擊加成，即使直接傷害為 0；非法出牌不消耗。玩家階段結束清除。
- 同一受益者最多保存一份下一擊加成，取較大值；新加成不能提高時，施放前拒絕並不支付資源。
- 「現在一起上」至少要有一位受益者能新增或提高加成才可施放；另一位保留較大的既有值。單人或隊友倒下時只給自己一份。

## 三、建議新增效果與 PlayerCombat 最小契約

目前 src/engine/types.ts 的 Effect 沒有封封蓄氣識別字；以下是語義契約與建議名稱，不代表這些識別字已存在。內容代理不可先在牌表引用未實作的名稱。

### 共同支付上下文

出牌前處理應產生一次性的解析上下文，至少能提供：

- qiBefore：出牌前蓄氣。
- qiSpent：本牌實際 S；多段、多目標共享同一值。
- qiSpendMode：定量上限或全部。
- cardType、cardId、cardUpgraded、合法受益者與目標。

qiBefore 與 qiSpent 是本次出牌快照，不應寫成下一張牌可重用的全域數值。傷害、蜷縮門檻、能力觸發與支援效果都讀同一份 qiSpent。

### 建議效果能力

| 建議識別字 | 最小語義 | 使用牌 |
|---|---|---|
| gainQi | 增加指定蓄氣，套用 0～12 上限並回報實得量 | C03、C04、C09、C10、C17、C18、C24、C28、C30 |
| damageSpendQi | 以一次 qiSpent 形成基礎值+係數×S 的普通傷害，支援單體、全體、多段、同目標與 ignoreBlock | C01、C05、C06、C13、C14、C15、C16、C26、C27、C31 |
| blockSpendQi 或 qiSpent 上下文 | 以同一次 qiSpent 計算蜷縮；若沿用既有 block，必須能讀 qiSpent 且只發一次貓步 | C19；C16、C21、C25、C32 的後續蜷縮或支援 |
| nextAttackBonusSpendQi | 扣本人的 S 後，將基礎值+係數×S 寫入受益者下一擊欄位，取大、不疊加、玩家階段結束清除 | C23、C32 |

既有一般傷害、蜷縮、抽牌、消耗卡片與 powers 可重用；不要為 32 張牌各自新增一個不可組合的效果識別字。

### PlayerCombat 建議欄位

目前 PlayerCombat 已按座位保存各玩家戰鬥狀態。最小新增契約如下：

- qi: number；整數 0～12，預設 0，依席位獨立。
- nextAttackBonus?: number；該玩家下一張攻擊的第一段首目標加成，沒有時為 0 或未設定；只保存較大值，合法攻擊使用後清除，玩家階段結束清除。
- fengfengTurnFlags?: { xunxi?: true; shoushi?: true; lianxi?: true }；記錄 C20、C21、C29 本人本回合是否已觸發；每次本人玩家階段開始清除，重連不得重新清除。
- energyGainBlockedThisPhase?: true；C30 的本玩家階段封禁旗標；所有能增加飯糰的入口都必須檢查，階段切換清除。
- C28 的持續效果優先沿用既有 powers 的 turnStart 形狀，不另造一個永久布林欄位。
- qiBefore、qiSpent、受益者與目標是單次 EffectCtx／牌面解析資料，不應永久放進 PlayerCombat。

任何重連或可保存的戰鬥快照都必須包含 qi、nextAttackBonus、能力本回合旗標與飯糰封禁狀態；正式倒下、撤離或戰鬥完成時依規格清除蓄氣。預覽與結算必須使用同一解析上下文。
