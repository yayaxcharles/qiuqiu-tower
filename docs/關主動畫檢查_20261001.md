## 怎麼量的

`tools/perf/boss_motion_check.mjs`（新工具，只開本機網址、無頭 Chrome 獨立設定資料夾）：直接開打 → 結束回合讓牠出招 → 打到第二階段 → 再出招 → 打死，

- 快網路：不限速。
- 慢網路：0.8 Mbps／300 毫秒、冷快取（每次新的設定資料夾）。分兩種：
  - 「開局馬上打」：開局後立刻進關主戰（最差情況）。
  - 「實際情境」：開局後在地圖停 2 分鐘再打（模擬一路打上來），每次出招前最多等 90 秒讓那一段的圖集到。

## 修法

1. **倒下時把畫布掛回立繪框**（主修）：`combat.ts` 新增 `showEnemyMotion`，`finishEnemyMotion` 的長倒下與短倒下兩條路都先掛回去再演。
2. **待機改畫立繪的那幾套不抓走路圖集**（慢網路）：那張從來不上畫面，卻被算進「這一套好了沒」。鐵爪第二階段的走路圖 735 KB 排在最後，
   害雷射與爆炸到了還要再等 20 多秒才演得出來（實測變身後 52 秒 → 28.6 秒）。`enemy-motion.ts` 的 `texturesOf`；畫布一建好也不先畫走路。
   同一批挨打時一律不播「挨打」（沒有這個片段，會退回走路）：站著時播了也看不到、只會在背景去抓走路圖；
   出招中被反彈打到也不再把出招換成走路、打斷收招（審查 低-2）。
3. **第二階段先下載、不解碼、不插隊**：第一階段那套好了之後，把第二階段的出招、爆炸圖集排進下載（`prefetchEnemyMotion`），
   不解碼、不算就緒，第一階段不多壓記憶體（09-28 稽核低-2 的顧慮）。**排在最後、不插隊**（審查 中：插隊會在慢網路把主角第一次用到的動作圖集擠到後面），
   變身那一刻照舊插隊；下載失敗的從快取拿掉，變身時重抓（審查 低-3）。
   效果：快網路第一階段一好就下載完，變身時只剩解碼；慢網路大圖集那一條還排著主角的圖，這兩張輪不到，等於變身才開始抓（變身後 23～29 秒），
   不會跟主角搶。第一版（`d7127e69`）插隊時，第一階段多打 40 秒的情境變身後等 0 秒，這個好處為了不擠主角放掉了。

4. **畫布一建好就畫該畫的動作**（補洞）：待機改立繪的那幾套建好時不再先畫走路，若剛好在「已倒下、不在等倒下」時才建，
   原本會記成倒下卻沒畫、變成空畫布；改成建立時就畫那個動作，等倒下中的記成待機、倒下那一拍從第一格開演。這條路實測沒走到，屬預防。

沒有降畫質、沒有縮短爆炸、沒有讓勝利畫面等圖。

**主角動作有沒有被擠到（審查 中，實測）**：0.8 Mbps／300 毫秒冷快取、地圖停 2 分鐘再打鐵爪，第一階段出五張延後下載動作的牌
