## 這兩包在做什麼

**甲包｜看得懂**——三個純美術缺口，一格動畫都不加（使用者拍板：會拉長遊戲節奏的動畫一律不做）：

1. **57 隻魔物的防禦姿勢**。`MonsterPose` 型別裡本來就有 `block`，但一張都沒生過，
   選圖也只認出招／挨打／待機。魔物縮起來擋你那一拍，畫面上牠還是站得直挺挺的待機圖，
   只有旁邊多一個「防禦 14」的小牌子——玩家看不出這回合不該硬打。
2. **六個沒圖示的狀態**：縮殼、飛行、鱗甲、沉睡、消散、虛化。
   `combat.ts` 早就指到 `status_curl`／`status_fly`／`status_plate`／`status_sleep`／`status_fade`／`status_phase`，
   但 `public/assets/icons/` 裡一個都沒有，`chip()` 只好退回寫名字。
3. **罐頭鋪老闆兩張表情**：成交、錢不夠。原本從頭到尾同一張臉；買不起的格子點下去更是整個畫面沒反應。

**乙包｜瘦身**——首載 11.07 MB，預算 9.5 MB，超了 16.6%。甲包還會再加 57 張圖，不一起做只會更糟。

魔物圖 306 張共 8.67 MB、平均 28 KB、幾乎全部存成 **460×46x**；
但畫面上小型只有 130×150、中型 180×210、大型才 230×280（`combat.ts` 的 `SPRITE_BOX`）。
小型等於每張多背三倍半的像素——這是乙包最大的一筆，而且**不用降畫質**，只是不再送沒人看得到的像素。

實測過四種設定（魔物 306 張的總大小）：

| 設定 | 大小 |
|---|---|
| 現況（一律 460、q72） | 8.67 MB |
| 2.0 倍、q74 | 7.20 MB |
| 2.0 倍、q62 | 6.77 MB |
| **1.75 倍、q74（採用）** | **約 5.9 MB** |
| 1.5 倍、q74 | 5.13 MB |

**降解析度比降畫質有效太多**（2 倍改 1.5 倍省 2.07 MB，q74 降到 q62 只省 0.43 MB），
所以畫質參數一格都沒動。倍率選 1.75 的理由：畫面 1280×720 等比放大，1080p 全螢幕剛好是 1.5 倍、
1440p 是 2.0 倍。把最細的三隻（狐仙、三味線貓、怨靈武者）拉到 1440p 的像素數並排比對過，
只有狐仙的尾巴細毛與法杖吊飾看得出略軟，另外兩隻分不出來。

球球與師父那 52 張維持 2 倍（640×640）：整場都在畫面上、又是最大的兩塊，多留一級值得，
而且只有 52 張，省不了多少。

**程式 333 KB 與樣式 82 KB 沒有動。** 那兩個超標是內容量體本身變大（271 條魔物、110 張牌都打包在 `src/content`），
要壓就得砍內容；而且壓縮後實際傳輸是程式 105 KB、樣式 18 KB。**使用者 2026-09-10 裁定「我覺得還可以 先不動」**，
所以 `npm run size` 的離開碼會一直是 1，別把它當成通過。

**最後補的一刀（意圖木牌）**：那七張是拿來當 `border-image` 九宮格的，只畫 9～12 像素的邊框，
圖卻存 1000×300。`border-image-slice` 用百分比、`border-image-width` 用 CSS 像素，**兩個都跟來源尺寸無關，
所以等比縮它是安全的**。縮到 320 寬：153 KB → 20 KB，瀏覽器實看木框完全正常。
