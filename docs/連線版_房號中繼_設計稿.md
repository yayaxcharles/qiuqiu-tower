# 連線版：房號中繼（Cloudflare Worker）設計稿

2026-09-14 深夜定案。使用者跟朋友實測「連不上對方」很多次之後裁定：**改走 Cloudflare 中繼**，貼碼直連留當備用。

## 一、為什麼

- 原本兩台瀏覽器直連（WebRTC 資料通道），只用 Google STUN 問「我的對外位置」，沒有 TURN 中繼。
  任一邊在手機網路（電信商多人共用一個對外位址）、對稱式 NAT、公司或學校網路，就穿不過去——
  畫面等 20 秒後說「連不上對方（兩邊的網路接不起來）」。這是網路結構，不是運氣。
- 這款遊戲每一步只傳幾個小訊息（打了哪張牌、對帳單），量非常小。讓兩台都**主動往外連**到 Cloudflare、由它轉送，
  哪種網路都連得上；順便把「貼兩次長碼」換成「講一個六位數房號」。
- 只做房號交換（signaling）不夠：位置換到了還是穿不過去，還得另租 TURN。所以中繼直接轉送整場遊戲。

## 二、架構

```
瀏覽器 A ──wss──┐                          ┌──wss── 瀏覽器 B
                Cloudflare Worker ── Durable Object「Room」（一個房號一個）
```

- **`worker/`**（Cloudflare Worker ＋ Durable Object，`wrangler.toml`／`src/index.ts`）
  - `GET /room/<六位數>?role=host|join&build=<打包編號>` → WebSocket。
  - 一個房號一個 Durable Object，最多兩條 socket（host、join），用 WebSocket 休眠 API，兩邊等對方出牌時物件睡著、不計時。
  - 不懂遊戲：一邊送來的文字原封轉給另一邊。開房登記好先回 `{"m":"relay","s":"hosting"}`（瀏覽器端等到這句才秀房號，不靠時間猜）；
    兩邊都到了各送 `{"m":"relay","s":"open"}`；一邊斷線送另一邊 `{"m":"relay","s":"closed"}` 再關掉它。
  - 殭屍房：瀏覽器每 25 秒送 `ping`，房間用自動回應回 `pong`（不吵醒物件）；鬧鐘每分鐘掃一次，超過 150 秒沒 ping 的當死了（4001）。
  - 拒絕原因 40 字以內（WebSocket reason 上限 123 位元組）；訊息超過 16 KB 直接丟掉。
  - 拒絕一律「先接受、再帶原因關掉」（直接回 4xx 瀏覽器只看到 1006、沒原因）：
    4409 房號有人在用、4404 找不到房號、4403 房間滿了、4400 版本不同、4000 對方離開。
  - 狀態就是「現在連著的 socket」，不存任何東西；房間用完自然空掉。
- **`src/net/ws.ts`**：實作跟 `rtc.ts` 同一個 `Transport` 介面，所以 `session.ts`（鎖步、對帳、號碼）一行不改。
  `hostRoom()` 抽六位數房號、連上、等 `hosting` 才回傳房號，`ready` 等 `open`；房號撞到 4409 就換一個（最多三次）。`joinRoom(code)` 回 `{ ready, cancel }`。
  兩者都給 `cancel()`：大廳離開畫面時（`app.disposers`）把還在等的連線收掉，連上之後才清掉 `cancel`（不然進地圖會把遊戲連線一起關了）。
  中繼的話（`m: 'relay'`）不交給遊戲。版本檢查在中繼做（連進去帶 `build`）。
- **大廳**（`src/ui/screens/lobby.ts`）：預設房號模式——開房顯示大字房號、加入輸入六位數；
  底下一顆「中繼連不上？改用貼碼直連（備用）」切回原本的 WebRTC 流程。
- **網址**：`src/net/ws.ts` 的 `DEFAULT_RELAY`＝`https://qiuqiu-relay.qiuqiu-tower.workers.dev`；本機對著 `wrangler dev` 測時用環境變數 `RELAY_URL` 蓋掉（`vite.config.ts` 的 `__RELAY_URL__`）。

## 三、部署與帳號

- Cloudflare 帳號：使用者的（`e7006c2a…`），免費方案，不綁信用卡。`workers.dev` 子網域 `qiuqiu-tower`（2026-09-14 用 API 註冊，儀表板的引導頁 404）。
- 命令列登入一次：`npx wrangler login`（家用機已登入；工作機要再登一次）。
- 部署中繼：`cd worker && npx wrangler deploy`。**跟網頁分開推**：網頁照舊 `sh tools/deploy.sh`。
- 額度：免費方案每天十萬次請求；一局朋友之間玩幾百則訊息，遠遠用不完。用完或 Cloudflare 掛掉的那天，大廳切「貼碼直連」還能玩。

## 四、驗證

- `tests/net/ws.test.ts`：假 WebSocket 走三條路（連上、被帶原因拒絕、等太久）、房號撞號重抽、中繼的話不交給遊戲。
- `tools/relay_e2e.mjs`：對著線上中繼跑真的兩人對連（開房→加入→來回 200 則順序→一邊關掉另一邊收到通知→三種拒絕）。**部署中繼之後手動跑。**
- 真人：使用者跟朋友兩台實測（手機網路也要試）。

## 五、沒做的

- 房號沒有過期：開房的人等十分鐘沒人來就自己放棄；Durable Object 本身不用清。
- ~~中繼不做重連：斷線就是斷線~~ → 2026-09-15 做了，見第六節。
- 兩個人以上：協定與房間都寫死兩人。

## 六、中途斷線接回（2026-09-15，使用者：「好」）

- **中繼**：一邊斷了不踢另一邊，留兩分鐘（`GRACE_MS`；沒關閉訊框的靜默斷線要先等鬧鐘判殭屍，90 秒門檻、每 30 秒掃，所以對方最慢約四分半才放棄）；storage 一個 `counts` 記每一邊「收到幾則」「轉了幾則」，加最近 200 則轉出去的原文（每則訊息讀 1 列寫 2 列；storage 壞了照樣轉送、只是接不回去）。
  同一個角色可能同時掛兩條 socket（半開的舊線），「對方那一條」一律拿最新接上的（`live()`），不拿 `[0]`。
  回來的人連同一個房號、同一個身分，帶 `resume=1&got=<自己收到幾則>`：中繼補給他漏掉的、再說 `open`（附「我收到你幾則」），
  他把中繼沒收到的補回來。兩個方向都照數字補，一則不多一則不少，所以 `session.ts` 一個字不用改。
  真的走（回標題、關分頁 `pagehide`、分岔）先說 `bye`，對方立刻收到 `closed`（附原因）。同一個人接回時舊的 socket 標成殭屍、直接換掉。
- **瀏覽器**（`ws.ts`）：關閉代碼 1006／1001／1011～1013／4001 當線路斷了，馬上、1、2、4、之後每 8 秒重試，兩分鐘放棄；
  4xxx 的拒絕（房間關了 4410、版本 4400…）不再試。期間送的訊息排在 `history` 裡，接回一起補。
  對外只多一個 `onStatus`：away／back（自己）、peerAway／peerBack（對方）。
- **畫面**：自己斷線中戰鬥不收操作（`canAct` 看 `session.suspended`）、罐頭鋪按買賣會搖頭，大廳掛琥珀色橫幅、接回就撕；對方斷線只掛橫幅、自己照玩。
- **順便修掉的舊洞**（審查 高-2）：同伴比我早進罐頭鋪的買賣以前會讓我判分岔停局，現在先留著、貨架掛上補套；他的「逛好了」也不再被「回到地圖清掉」洗掉（沒人接的動作記「第幾張走格子的票之後到的」）。
- **沒做**：貼碼直連那條路不接回；兩邊同時斷超過兩分鐘就散了；斷線期間對方送超過 200 則接不回去（正常對局到不了）。
- 驗證：`tests/net/ws.test.ts`（假 socket：接回補收補送、拒絕不再試、兩分鐘放棄、排隊補送、bye）、`tools/relay_e2e.mjs`（線上中繼真的斷一次再接回）。
