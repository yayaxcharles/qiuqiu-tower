# 怪物朝向修正

日期：2026-09-20。

老鼠的 `rat-base.webp` 待機與受擊原圖朝左，`rat-attack.webp` 攻擊原圖朝右。舊設定誤將全部素材標為朝右，統一鏡射使待機與受擊背對左側我方。

- 待機與受擊增加動作層級 `mirror: false`；攻擊及忍者素材保留原有鏡射。
- 畫布依每個動作的實際翻轉方向計算邊界，並將繪製的腳底固定在同一座標；切換朝向設定不移動畫布。
- 同步修改匯入工具及資產紀錄。直接從既有 Godot 來源重新計算資料，與目前 `enemy-motion-data.json` 完全一致，避免下次匯入恢復錯誤設定；原圖未修改。
- 改正舊測試「兩種原圖全部朝右」的錯誤前提，檢查兩種怪物各動作的翻轉，以及變換後腳底座標。
- 本機戰場實看：兩隻老鼠待機已朝向左側球球；實際結束回合後，記錄到待機 `scaleX=2`、攻擊 `scaleX=-2`，畫布水平定位皆為 `translateX(-124px)`，出手後回到朝左待機。診斷已清除。

## 全怪物素材稽核

- 逐圖檢查 111 種怪物使用的 116 組外觀，共 501 張姿勢圖，以及塔主三階段的 23 張專用圖；另檢查兩種逐格怪物的 39 個畫格。
- 核對四位角色與怪物各階段的 484 條外觀解析路徑，包含鏡像、召喚物及缺圖時的待機替代。全數指向已檢查素材。
- 501 張怪物原圖中，403 張朝左、62 張正面、26 張倒地、9 張沒有明確左右方向，另有 1 張朝右。倒地、翻滾、無臉尾巴等沒有明確左右方向的素材保留原樣。
- 唯一需要修正的靜態圖是 `red_oni_hurt.webp`。在 `combat.css` 對赤鬼受擊圖單獨設定 `scale: -1 1`，使朝向與待機一致。獨立的 `scale` 不會被既有受擊震動的 `transform` 蓋掉。
- 推送前建置稽核補正：正式素材會更名為 `red_oni_hurt-<雜湊>.webp`，朝向選擇器同時匹配原始與雜湊檔名，避免只在開發伺服器生效。
- 瀏覽器並排目視確認赤鬼待機、攻擊、受擊；受擊圖計算樣式為 `scale: -1 1`，套用受擊狀態後同時維持 `animation: shake`。臨時檢查頁已關閉。
- [逐圖紀錄](enemy-facing-audit.json) 保存全部 524 張靜態圖與 5 張動畫圖集的 SHA-256、原圖朝向、鏡射設定及檢查理由。[回歸測試](../tests/ui/enemy_facing_audit.test.ts) 核對素材清單、雜湊及實際外觀解析路徑，替換或新增素材時須重新稽核。

驗證結果：五個相關測試檔共 119 項通過；全套 1,765 項通過、5 項略過；正式建置通過。全量檢查涵蓋素材與解析路徑，並未逐一實戰遊玩全部 111 種怪物。
